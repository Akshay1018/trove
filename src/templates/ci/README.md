## Common Customizations

### Database Configuration
All templates use Handlebars conditionals (`{{#if}}`) to include database-specific configurations:

```yaml
{{#if useMongoDB}}
# MongoDB specific configuration
{{/if}}
```

To modify database settings:
1. Locate the service configuration section in your template
2. Update environment variables, ports, or health check settings
3. Add any additional database-specific configuration

### Node.js Version
Change the Node.js version by updating:
- GitHub Actions: `node-version: '18'` in the setup-node step
- GitLab/Bitbucket: `image: node:18` at the top of the file

### Test Coverage
Customize coverage reporting:
- GitHub Actions: Modify the `codecov/codecov-action` step
- GitLab: Update the `coverage` regex pattern
- Bitbucket: Adjust the coverage artifacts path

## GitHub Actions
File: `workflow.yml`

### Adding New Jobs
```yaml
new_job:
  needs: [existing_job]  # Dependencies
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    # Add your steps here
```

### Modifying Triggers
```yaml
on:
  push:
    branches: [ main, develop, feature/* ]  # Add branches
  pull_request:
    branches: [ main, develop ]
```

### Custom Environment Variables
```yaml
env:
  CUSTOM_VAR: ${{ secrets.CUSTOM_SECRET }}
```

## GitLab CI
File: `gitlab-ci.yml`

### Adding New Stages
```yaml
stages:
  - test
  - build
  - deploy
  - your_new_stage
```

### Custom Job Templates
```yaml
.custom_template: &custom_template
  script:
    - echo "Reusable steps"

your_job:
  <<: *custom_template
  stage: your_new_stage
```

### Environment-Specific Variables
```yaml
deploy_staging:
  variables:
    APP_ENV: staging
```

## Bitbucket Pipelines
File: `bitbucket-pipelines.yml`

### Adding Custom Pipes
```yaml
- pipe: atlassian/aws-elasticbeanstalk-deploy:1.0.0
  variables:
    AWS_ACCESS_KEY_ID: $AWS_ACCESS_KEY_ID
    AWS_SECRET_ACCESS_KEY: $AWS_SECRET_ACCESS_KEY
```

### Custom Caching
```yaml
definitions:
  caches:
    custom: path/to/cache
```

### Adding New Services
```yaml
definitions:
  services:
    redis:
      image: redis:latest
```

## Environment Variables

### Required Secrets
- GitHub Actions:
  ```yaml
  DOCKER_USERNAME
  DOCKER_PASSWORD
  ```

- GitLab CI:
  ```yaml
  CI_REGISTRY_USER
  CI_REGISTRY_PASSWORD
  ```

- Bitbucket Pipelines:
  ```yaml
  DOCKER_HUB_USERNAME
  DOCKER_HUB_PASSWORD
  ```

### Adding Custom Secrets
1. Add secrets in your platform's settings
2. Reference them in the CI configuration:
   - GitHub: `${{ secrets.SECRET_NAME }}`
   - GitLab: `$SECRET_NAME`
   - Bitbucket: `$SECRET_NAME`

## Troubleshooting

### Common Issues

1. **Docker Build Fails**
   - Verify Docker credentials are set correctly
   - Check if Dockerfile exists in the root directory
   - Ensure Docker daemon is running in the CI environment

2. **Database Connection Issues**
   - Verify service container health checks
   - Check port mappings
   - Ensure environment variables are correctly set

3. **Cache Issues**
   - Clear cache if dependencies are not updating
   - Verify cache paths are correct
   - Check cache key configuration

4. **Test Coverage Reporting**
   - Ensure coverage reports are generated in the correct format
   - Verify coverage paths match the CI configuration
   - Check if coverage tokens/credentials are set

### Platform-Specific Solutions

#### GitHub Actions
```yaml
# Debug using tmate session
steps:
  - name: Setup tmate session
    uses: mxschmitt/action-tmate@v3
    if: ${{ failure() }}
```

#### GitLab CI
```yaml
# Enable debug logging
job:
  script:
    - set -x  # Enable debug mode
    - your commands
```

#### Bitbucket Pipelines
```yaml
# Enable SSH debugging
- step:
    script:
      - add-ssh-key.sh  # Custom debugging script
      - your commands
```
