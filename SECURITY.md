# Security Policy

## Supported Versions

Trove is an actively developed open-source project. Security fixes are prioritized for the latest stable release.

| Version | Supported |
| ------- | --------- |
| Latest stable release | :white_check_mark: |
| Older releases | :x: |
| Pre-release and development builds | :x: |

Users are encouraged to upgrade to the latest stable release to receive security fixes and other important improvements.

If a vulnerability affects multiple releases, the maintainers will determine which versions require fixes based on severity, impact, and feasibility.

## Reporting a Vulnerability

The Trove maintainers take security vulnerabilities seriously. If you discover a potential security issue involving Trove, please report it responsibly.

### How to Report

**Please do not disclose exploitable vulnerabilities in public GitHub issues, pull requests, or discussions.**

Use GitHub's private vulnerability reporting feature for this repository, if available:

https://github.com/Akshay1018/trove/security/advisories/new

If private vulnerability reporting is unavailable, please contact the repository maintainers privately through an appropriate contact method listed on the repository's GitHub profile.

### What to Include

When reporting a vulnerability, please include as much of the following information as possible:

- A clear description of the vulnerability.
- The affected Trove version, Node.js version, and operating system.
- Steps to reproduce the issue.
- The potential security impact and attack scenario.
- A proof of concept or minimal reproduction, if available.
- Any suggested mitigation or fix, if known.

Please avoid including real credentials, access tokens, personal information, or other sensitive data in your report.

### Response and Resolution Process

- **Acknowledgment:** The maintainers aim to acknowledge reports within 7 calendar days.
- **Assessment:** The maintainers will review the report, attempt to reproduce the issue, and assess its severity and impact.
- **Updates:** Reporters will be kept informed of significant developments as reasonably possible.
- **Accepted reports:** The maintainers will work toward a fix, prioritize the issue according to severity, and coordinate a responsible disclosure where appropriate.
- **Declined reports:** If a report is determined not to be a security vulnerability or is outside the project's scope, the reporter will be informed of the reasoning where reasonably possible.
- **Disclosure:** Public disclosure should be coordinated with the maintainers so that users have a reasonable opportunity to apply available fixes.

The acknowledgment target is not a guarantee of a fix or resolution within a specific timeframe. Resolution time depends on the severity, complexity, and available resources.

### Scope

Security reports may include, but are not limited to:

- Remote code execution or command injection.
- Path traversal or unsafe file writes during project generation.
- Exposure of secrets or sensitive configuration.
- Insecure handling of user-provided input.
- Vulnerable dependencies that create a demonstrable security impact.
- Security weaknesses in generated application templates or CLI behavior.

Reports should demonstrate a plausible security impact on Trove, its users, or applications generated by the tool.

### Responsible Disclosure

Please give maintainers a reasonable opportunity to investigate and address a vulnerability before publicly disclosing technical details.

We appreciate the time and effort of security researchers and community members who help keep Trove and its users safe.
